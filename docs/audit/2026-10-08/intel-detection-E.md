## (c) Tenant and RBAC issues

1. Cross-tenant detection crediting in BAS: the DetectionRule query has no org filter (src/simulation/engine.py:625-631), and neither do the LogEntry and CorrelationEvent evidence queries (engine.py:553-560, 571-578). One tenant's rules or logs can mark another tenant's test "detected".
2. GET /simulation/posture returns the latest SecurityPostureScore across all orgs (src/api/v1/endpoints/simulation.py:841-845).
3. GET /simulation/posture/gaps picks the latest AttackSimulation from any org when no id is given (simulation.py:893-899). generate_gap_analysis has no org check (engine.py:1623).
4. IDOR: GET /simulation/simulations/{id} (simulation.py:223), /start (simulation.py:283-285), /pause (simulation.py:316), /cancel (simulation.py:343), /progress (simulation.py:369) and /report (simulation.py:399) all look up by id only. `SimulationOrchestrator._get_simulation` (engine.py:815-820) and `PostureScorer._get_simulation` (engine.py:1687) have no org filter.
5. Dashboard trend: posture scores are filtered by org only when org_id is not None (simulation.py:1055-1064). The same "if org_id is not None" pattern appears at simulation.py:174-175 and 962-964, so a user with organization_id=None sees all tenants.
6. The WebSocket channel subscription has no authorization (src/api/v1/endpoints/websocket.py:94-96; src/services/websocket_manager.py:68-71). Any authenticated user can subscribe to `agents:<other_org_id>` and receive agent command stdout previews and SIEM matches. PurpleTeam relies on this channel (PurpleTeam.tsx:71,124).
7. GET /attack/coverage counts DetectionRules from all tenants (src/attack/service.py:165-167).
8. GET /phishing_sim/training/modules has no auth dependency (src/api/v1/endpoints/phishing_sim.py:1697).
9. The phishing_sim tasks load campaign, target and template by id without an org filter (src/phishing_sim/tasks.py:136-170). Low risk, because the ids come from the server.
10. RBAC: no role checks anywhere in simulation.py or phishing_sim.py (grep for require_role returns nothing, though `require_role` exists at src/api/deps.py:180). Any authenticated user, including read-only analysts, can execute atomic tests on live endpoints (simulation.py:548, 746), launch real phishing emails to staff (phishing_sim.py:730), hand-record phishing outcomes that change other users' awareness scores (phishing_sim.py:1171), and issue training certificates (phishing_sim.py:1866). Only POST /attack/sync is gated, to superusers (attack.py:105).
11. `run_continuous_validation` uses `created_by="system"` (src/simulation/tasks.py:268). ENG:1494-1497 notes this violates the users FK. The task is not scheduled anyway.
