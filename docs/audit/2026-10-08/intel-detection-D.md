## (c) Tenant / RBAC / security issues

1. **CRITICAL arbitrary file read (LFI):**
   - POST /dfir/evidence accepts any `storage_location` (dfir.py:432; src/schemas/dfir.py:98).
   - GET /dfir/evidence/{id}/download serves it with `FileResponse` and no confinement to DFIR_UPLOAD_ROOT (dfir.py:405-416).
   - The UI exposes it as a free-text field (DFIRDashboard.tsx:1185).
   - Any authenticated user can exfiltrate e.g. `/opt/pysoar/.env`. Row creation is currently masked by the CoC schema 500; fixing that bug re-opens the hole.
   - The same handler is an open redirect for http/https/s3 locations (dfir.py:400-402).
2. **Tenant reassignment via update:** PUT /deception/decoys/{id} `setattr`s `organization_id` from the request body (deception.py:313-317). The UI sends `'default'` (DeceptionTech.tsx:876).
3. **Client-supplied org fallback** when the user has no org:
   - deploy_decoy, deception.py:156 (UI sends 'default', DeceptionTech.tsx:709)
   - generate_token, deception.py:586
   - create_campaign, deception.py:1104
   - DFIR upload falls back to "default", dfir.py:508
4. GET /deception/interactions/timeline has no org filter on the interactions or the decoy lookup (deception.py:898-913). It leaks other tenants' interactions by decoy_id.
5. POST /deception/interactions/{id}/investigate correlates by source_ip across all tenants (deception.py:1000-1010). Its decoy lookup is unscoped (deception.py:1039-1041).
6. GET /deception/decoys/{id}: the recent-interactions query is unscoped (deception.py:268-273). Low risk, since the decoy is org-checked first.
7. GET /deception/campaigns/{id}: the decoy lookup (deception.py:1206-1209) and the effectiveness interaction counts (deception.py:1298-1312) are unscoped. Low risk, since the ids come from an org-scoped campaign.
8. DFIR create_case checks for duplicates globally (dfir.py:216-224). This enables cross-tenant case-number enumeration and blocks reuse of a number across tenants.
9. **Pervasive `if org_id:` / `org_id is not None` guards:** a user with a null organization_id gets unscoped, all-tenant results on every list and get. Examples: dfir.py:89-90, 139-141, 314-315, 1167-1169; deception.py:210-212, 635-637, 846-848, 1414-1422.
10. **No RBAC** anywhere in dfir.py or deception.py (no `require_role`/`AdminUser`; those exist at src/api/deps.py:180, 201). Any authenticated user, viewers included, can:
    - close or modify cases and set `court_admissible` (dfir.py:246-270)
    - append chain-of-custody entries and overwrite evidence hashes (dfir.py:634-704)
