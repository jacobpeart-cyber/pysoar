# Audit A: ThreatIntel.tsx + DarkWebMonitor.tsx (threat-intel / iocs / darkweb)

Grade counts (40 feature rows): REAL 12 | PARTIAL 14 | BROKEN 9 | FAKE 2 | UI-ONLY 3 | STUB 0

Root cause that touches most ThreatIntel rows: feed ingestion never sets `organization_id`. `FeedManager.poll_feed` adds `ThreatIndicator(...)` at src/intel/feeds.py:812-833 with no org, and the built-in feeds are created with org NULL at startup (src/main.py:152-158 -> src/intel/feeds.py:1136-1149). Every `/threat-intel` read filters `organization_id == org_id` whenever the caller has an org (intel.py:365-367, 474-477, 679-681, 1084-1086). Result: a user who belongs to an organization sees no built-in feeds and no feed-ingested IOCs. A user with no org sees every tenant's rows.

## (c) Tenant / RBAC issues

1. Feed-ingested indicators carry no organization_id. src/intel/feeds.py:812-833 (poll_feed insert) and feeds.py:1039 (_deduplicate_indicator). Built-in ThreatFeed rows are org NULL (feeds.py:1136-1149, called at src/main.py:152-158). With the strict filters below, org users never see feed intel. Decide: either global intel (filter `org == X OR org IS NULL`, as src/remediation/tasks.py:539-542 already does) or per-org feeds.
2. `if org_id is not None` fallback: a user without an org sees every tenant's rows. intel.py:365-367 (stats), 474-477 (lookup, `True` clause), 680-681, 736-737, 761-762, 791-792, 820-821, 928-929, 957-958, 1085-1086, 1156-1157, 1177-1178, 1203-1204, 1225-1226, 1258-1259, 1285-1286, 1344-1345, 1399-1400, 1437-1438, 1499-1500, 1635-1636, 1772-1773, 1912-1913, 2032-2033; iocs.py:95-96 (get_ioc_or_404); aliases.py:57 (_safe_list).
3. `_load_intel_integrations` does not filter InstalledIntegration by organization (intel.py:107-114). One tenant's VirusTotal/AbuseIPDB key would serve every tenant's lookups (currently masked by the decryption bug at intel.py:118). The lookup cache key (provider, type, value) is also not org-scoped (intel.py:573-574).
4. GET /iocs `list_iocs` has no org filter at all (src/api/v1/endpoints/iocs.py:131-181). It is called by frontend/src/lib/api.ts:291, so every tenant's IOCs are exposed.
